# glean 1.0 design

Date: 2026-08-17
Status: approved concept, awaiting implementation planning
Scope: the production-ready major release, everything that lands before glean 1.0

Visual reference: `.inst/glean-workspace-mockup.html`, kept out of the public repo.

## Context

glean is a Wails v2 desktop app: Go backend bound straight to a React frontend, one native binary per platform. Every note is a star in a night sky. Today the data lives as flat JSON in the app config dir, there are two views, Home and the Sky canvas, and every other surface is a popup window over the sky. This design restructures all of it for 1.0.

## 1. Identity and brand

glean is written lowercase everywhere, even at the start of a sentence. It is a whisper, not a shout.

The vocabulary is one metaphor all the way down:

| term | meaning |
|---|---|
| glean | the app |
| Sky | what you open, the container. Replaces "vault" |
| Constellations | the patterns the sky shows: stars and the inferred trail lines between them. Replaces "graph view" |
| Stars | notes |
| trail lines | the connections between stars, inferred from behavior, never authored |

The identity line: Obsidian is a vault you open, glean is a sky you look up into.

The fusion principle: a vault and a graph are two separate places in Obsidian. In glean they are the same sky. The sky you open is the sky you look at. There is no hidden data layer and no separate viewing mode, because the constellations ARE the structure. This fusion is the signature glean owns.

Scope doc alignment: section 12 keeps graph view as a declared structure out of scope forever. Constellation lines are inferred, never authored.

## 2. Versioning and release order

Current state: 0.0.1, two commits, the baseline tag deleted and the history reworded, no real release.

1.0 is the first release where glean promises not to break people. Everything breaking happens before it, in this order:

1. Sky folder md model, the last breaking change, the data model
2. The workspace restructure, breaking UI
3. First-run wizard
4. Production packaging: Windows is the 1.0 promise, the only platform tested by the author, shipping as an NSIS installer. Linux AppImage and macOS builds ride along as untested companion artifacts, unsigned, clearly labeled. Signing and notarization need a real Mac and an Apple Developer account, deferred until macOS earns it
5. Sync stance: folder-based DIY, no cloud

After 1.0, semver discipline: breaking changes cost a Major, features are Minors, fixes are Patches.

## 3. The workspace

The main page is no longer the sky. The sky becomes the left navigator, and the editor becomes the main pane. Popups become panels.

Shell, left to right, top to bottom:

- Tab bar: wordmark, open stars as tabs, a new star tab, the settings icon
- Left panel: the Sky, glean's version of the graph view. Stars are notes, constellations are the patterns. Click a star, it opens in the main editor. A search pill filters the sky
- Main pane: the editor, the big knowledge fix, detailed in section 4
- Right panel: note details, created, visits, brightness, linked stars, plus the note actions: wish, delete, edit
- Status bar: word count, save state, sky name, version. No sync state in 1.0, there is no cloud to sync with
- Settings: a pane, not a modal

Every current overlay maps to a panel:

| today | 1.0 |
|---|---|
| Home page | Welcome greeter |
| Sky canvas full screen | Sky panel plus a full-screen mode |
| NoteOverlay popup | right details panel |
| EditOverlay modal | main editor pane |
| NewNotePrompt modal | new star tab |
| StatsOverlay | stats view |

Welcome is a greeter, VSCode style: it shows on first run and when nothing is open, and hides the moment a star opens. New users meet the greeting, veterans land straight in their sky and editor.

The stats view carries one fix: the chart keys dates in UTC while the backend records local dates, so in any non-UTC timezone the bars can render empty. The fix is to agree on one clock, local dates. This shipped in the workspace milestone.

The trail strip: the active note's linked stars render as clickable chips in the editor header. Backlinks as navigation, the fusion principle inside the editor. This replaces breadcrumbs, rejected because a flat sky has no hierarchy, and Obsidian's passive backlinks panel.

## 4. The editor

The writing surface is a plain textarea, upgraded and given room, with a preview toggle that renders through the existing hand-rolled markdown renderer. No editor engine in 1.0. Writing stays raw markdown, one toggle from pretty. Live preview editing, Obsidian style, is rejected for 1.0: it is a different product, not a better editor, and it does not serve the big-knowledge concern.

Autosave contract:

- 1.5s debounce, unchanged
- Flush on tab close, window blur, and app quit through the existing Wails lifecycle hooks
- Ctrl+S flushes immediately
- Content lives in .md files, so a crash costs at most 1.5 seconds of typing
- Status bar shows saved and unsaved. A warm dot on the tab means dirty

External edits:

- When the file on disk differs from what is open, the tab shows a small banner: "File changed on disk" with Reload and Keep mine
- Files are truth, but never silently

The outline rail:

- A collapsible strip at the left edge of the editor pane
- Lists headings from the same regex the renderer uses
- Click to jump via character offset and scroll. The heading you are in highlights as you scroll
- Hidden when the note has fewer than three headings
- Updates live with a debounced scan
- The same headings feed the command palette later

Tabs:

- One tab per open star: species dot, title, close button
- Clicking an already open star focuses its tab. New stars get new tabs
- The "+" tab keeps the title prompt, then lands as a tab
- No cap, horizontal scroll when overflowing. Drag reorder deferred
- Tabs restore on launch from .glean/workspace.json: open ids in order plus the active id
- The greeter shows on first run and when all tabs are closed
- The active tab's star is highlighted in the Sky panel. The details panel follows the active tab

## 5. The Sky folder md model

The last breaking change and the anchor of the versioning order. Principle: content is files, behavior is JSON. What the user wrote is plain markdown they own forever. What glean inferred lives in a sidecar.

Folder layout:

```
My Sky/
├── First spark.md
├── Dim glow.md
└── .glean/
    ├── sky.json      sky name, first run flags, settings
    ├── notes.json    registry: id, title, species, stage, world position, visits, timestamps
    ├── trails.json   adjacency pairs
    └── stats.json    daily counts, streaks, milestones
```

The only file outside the folder is a small pointer in the app config dir, app.json with the sky path, because the folder cannot point to itself.

Note files:

- The file is named after the title, Windows-safe: strip `<>:"/\|?*`, trim dots and spaces, dedupe as `Steady light 2.md`
- Rename the note, the file renames with it
- The body is the entire file. No title header, no YAML frontmatter. The nothing-authored rule survives

Scanning and import:

- glean scans the Sky folder on launch and on window focus
- Any md file without a registry entry is a new star. Migration from Obsidian is copying the vault folder into the Sky. Import is not a feature
- External edits are picked up on the next scan

Legacy migration:

- One time, automatic, at the first launch of 1.0: read the legacy JSON in the config dir, write every body out as md, build the registry, leave the old files untouched as an archive

Sync stance:

- No cloud backend in 1.0
- Put the Sky folder in OneDrive or Syncthing. Markdown syncs everywhere. The JSON sidecars are small and written atomically, temp file plus rename, so sync tools never see half-written files
- One honest limitation: the same sky open on two machines means JSON conflicts are last-write-wins. Accepted for 1.0, and the folder model does not block a real sync later
- The external-edit banner covers content files. Behavior JSON resolves last-write-wins by design

API changes:

- GetNotes stops loading bodies, the sky only needs titles, species, and coordinates
- Bodies load lazily when a note opens, one file read
- The Go store splits into a registry store and a note file store, each with one job

## 6. First-run wizard

A new glean user is someone with no Sky, and the marker is the pointer file. app.json in the config dir holds the sky path.

- No app.json or no sky path: first run, the wizard. After setup the pointer is written and the wizard never shows again
- Pointer exists: normal launch, straight to the sky. Missing notes are not a new user, the greeter shows
- Pointer exists but the folder is missing: not first run, a lost sky. A recovery screen, "Your Sky is missing", with Locate folder or Create a new one. Never overwrite the pointer silently

The wizard has two paths:

1. New sky: glean wordmark and the tagline, then "Setting up your Sky." / "What's the name of your Sky?" with the default folder Documents under the sky name and a "choose location" button opening the native folder dialog
2. Existing folder: a quiet "Use an existing folder instead" link switches to folder-first, the name pre-fills from the folder name, and the scan turns any markdown inside into stars

Then "Your Sky is ready." with the first star prompt, the empty sky behind it. The sky name is stored in sky.json and shows up in the greeting, the breadcrumbs, and the title bar.

Name validation: same sanitizer as note files, strip `<>:"/\|?*`, trim dots and spaces, cap at 60 characters, reject reserved names like CON and NUL, Create disabled until valid with a live hint. The folder name is the sky name; the display name in sky.json survives folder renames.

Legacy migration: at the end of the wizard, offer "Found N notes from an older glean. Import them?" only when legacy files exist, the new sky's registry is empty, and it has not been skipped before. Legacy files are glean.json, adjacency.json, and activity.json in the config dir. Import preserves ids, world positions, species, stage, visits, timestamps, copies trails and stats, writes the md files with the same dedupe rules, and reports a summary if any fail, "Imported 12 of 13", no silent partials. Legacy files stay untouched as the archive.

## 7. No plugins, everything in core

Option A, approved. There is no plugin marketplace and never will be. The settings pane is the control surface. Everything Obsidian makes plugin-dependent, glean ships in core: word count already exists, export is the md model itself, and anything else lands in core only if it earns its place.

## 8. Component sourcing

The frontend is React in a webview, so any browser component works. Rules:

- Source from 21st.dev and shadcn only. MIT licensed, copy the source into the repo, own the code
- No component library dependencies. React Bits and the import model are rejected. glean is lightweight, one binary, nothing you do not own
- Borrow mechanics, never the look. Every copied component is re-skinned with the tokens in theme.js: the background, the borders, the accent, the motion tokens. A default-styled component instantly looks like a template site
- Convert TypeScript to JSX on paste. The project is JSX and stays JSX
- Keep MIT license headers, or collect them in a THIRD_PARTY file

Mapped surfaces: command palette for star search and fly-to, resizable panels for the workspace chrome, tabs for open stars, toggles and sliders for the settings pane, progress steps for the wizard, toasts for save and sync status.

## 9. Research grounding

- Obsidian's graph view is beautiful and almost completely useless at scale. glean makes the graph the primary navigation, which is the fix
- Plugin fatigue is Obsidian's top friction: breaking updates, abandoned plugins, full filesystem access. glean ships everything in core
- Missing basics in Obsidian, word count, export, calendar, are plugin-dependent. glean keeps basics in core, and anything else lands only if it earns its place, matching section 7
- The notes graveyard problem at thousands of notes is answered by brightness, warmth, and constellations as rediscovery
- Obsidian is closed source. glean is open source, and for a notes app the code being readable is part of the trust story: files you own, code you can read
- Obsidian is Electron-heavy, bundled Chromium and Node. glean on Wails is one small binary with no bundled engine, the lightweight pillar kept literally
- Local-first md is the trust anchor. The Sky folder model is that promise kept literally

## 10. Known issues carried into the build

- Konva scale warnings: Sky.jsx passes a number to the scale prop which expects x and y. Lines 1357, 1368, 1379
- Stats chart timezone: see the workspace section
- Windows window on double-click: verify the window shows on taskbar double-click, item from the vault open work
- Animation loop watch: the sky's meteors and comets may not animate between interactions, item from the analysis
- Stray "a" in note bodies during a preview session: transient, likely an automation artifact, watch it
- GetPalette guard: already fixed, browser mode no longer crashes

## 11. Open before implementation

- Wire the sky scan into app launch and window focus. The scanner exists and is tested, the app never calls it, so external md files do not become stars yet
- Wire the per-tab dirty dot, rendered but never driven
- Decide whether the details panel keeps an edit action now that the editor is the main pane
- Whether the first-run wizard survives in 1.0. The pointer gate and migration offer have real jobs, the brand moment is the question. The bootstrap already works without it
- CI now attaches binaries to Releases on tag pushes, carries a Windows NSIS installer, and a Linux AppImage. The macOS dmg step is deferred with the platform stance

## 12. Release pipeline

Tag push, the CI builds four targets and attaches them to the Release page: glean-setup.exe from NSIS, glean-x86_64.AppImage from linuxdeploy, and the macOS app bundles zipped. No zips or tarballs beyond what the platform forces. GitHub auto-attaches source archives. The app icon lives at packaging/appicon.png, a placeholder star in the theme colors, staged to build/appicon.png before every wails build, which derives icon.ico and icon.icns. The real brand icon replaces the placeholder when the brand work lands.
